# 開発・検証・公開手順

最初に[AGENTS.md](../AGENTS.md)を読んでください。**各作業でMarkdown更新・GitHubへのpush・既存Sitesへのデプロイを実施します。文書のみでも反映し、都度の許可確認は不要です。**

## 作業開始

1. `git status --short`、現在のブランチ、`git remote -v` を確認する。他者の変更がある場合は保持する。
2. [引き継ぎ情報](HANDOFF.md)、[ゲーム仕様](GAME_SPEC.md)、[変更履歴](../CHANGELOG.md)から現在の仕様と検証状況を確認する。
3. 実装を伴う場合は[設計・レビュー・承認の手順](IMPLEMENTATION_WORKFLOW.md)に従い、設計書を作成して別エージェントのレビューを受ける。
4. 指摘解消後の設計書の版について、レビュー担当エージェントの承認を記録する。ユーザーの設計書レビュー・承認待ちは設けない。承認前は実装しない。
5. 承認記録を残し、承認済み設計書に沿ってソース・テスト・関連ドキュメントを変更する。設計変更は再レビュー・再承認を経る。

```sh
git status --short
git branch --show-current
git remote -v
```

現行のGitHubリポジトリは `https://github.com/tanaka27/gptwork-rpg-game.git`、共有ブランチは `main` です。npm installやビルドは必要ありません。一時ファイルはGit対象外の `work/` に置きます。

## ローカル起動

通常のローカル環境では次を実行します。

```sh
python3 -m http.server 8080 --directory dist
```

`http://localhost:8080` を開きます。`index.html` は `combat.js`、`game.js` の順で読み込みます。CSS/JSの配信更新時はHTMLの `?v=...` を更新し、必要ならブラウザを再読み込みしてください。

Sitesの管理された環境では、一般のローカルサーバー手順よりSitesスキルのプレビュー手順を優先します。これまでの環境は `SITES_MANAGED_LINUX_CONTAINER=1` でしたが、指定のブラウザQA経路が見つからず画面確認を省略しています。次の環境でも同じ制約があると決めつけず、利用可能なツールと最新スキルを確認してください。

## 必須チェック

```sh
node --check dist/combat.js
node --check dist/game.js
node tests/game.test.cjs
git diff --check
```

テストはNode.js標準の `fs`、`vm`、`assert` を使い、DOM・localStorage・乱数・待機時間をモックします。

| 検証対象 | 内容 |
| --- | --- |
| マップ | 双方向接続、隣接移動、ワープ禁止、戦闘中の移動禁止、解放条件 |
| 進行 | 全エリアのボス到達と撃破、レベルアップ、街への復帰 |
| アイテム等 | 購入、装備、宿泊、素材売却 |
| 素材 | 確率の境界値、素材候補、保存 |
| セーブ | 旧セーブ移行、位置と素材の再読込 |
| リセット | 確認表示／キャンセルで維持、OKで削除、次の操作で保存再開 |
| 戦闘計算 | 最低0、攻撃力・守備力に対する単調性、物理スキルの会心・守備無視、かすり当たり、強攻撃・防御の合成 |
| スキル | MP消費、威力、賢さ成長、魔法の受け手能力非依存、回復上限 |

このテストは実ブラウザ、CSSレイアウト、フォーカス、タッチ、音声再生、実際のタイマーを検証しません。変更に応じた意味のあるテストを追加し、ブラウザ確認の有無も記録してください。文書のみの変更ではリンクと記載内容の整合性を確認します。

## ブラウザ確認を行える場合

- PC幅とスマホ幅でヘッダー、地図、素材タブ、賢さとスキル種別が読めること。
- 隣接ノードだけへ移動でき、街で宿泊・購入・素材売却できること。
- 通常攻撃、物理スキル、魔法、回復、防御、敵の3ターン目の強攻撃。
- セーブを保持して再読み込みしたときに進行が戻ること。
- リセットのキャンセルで維持し、OKで削除されること。検証には作業用のブラウザデータを使うこと。
- ブラウザコンソールのエラーと、操作中の二重入力・表示崩れ。

## Markdown更新とGitHubへのpush

ユーザーから、各作業のGitHub `main` へのpushと既存Sitesへのデプロイは継続的に事前承認されています。作業ごとの確認質問は不要です。関連チェックを済ませたら、コミット・push・デプロイ・成功確認まで続けて実行します。ツールや実行環境の必須承認手続きには従ってください。

1. 仕様変更を `GAME_SPEC.md`、構成・制約を `HANDOFF.md`、手順変更をこの文書へ反映する。
2. `CHANGELOG.md` に実装内容・検証内容・未検証範囲を記載する。利用者向けの内容が変わればREADMEも更新する。
3. 関連チェックを通し、差分をレビューする。
4. 対象ファイルを明示してステージし、コードと関連Markdownをコミットする。
5. GitHubへpushし、成功と作業ツリーを確認する。

```sh
git diff --check
git diff --stat
# 実際に変更したファイルだけを指定する
git add README.md AGENTS.md CHANGELOG.md docs/
# コードを変更した場合は該当する dist/ と tests/ のファイルも追加する
git diff --cached --stat
git commit -m "Describe the completed change"
git push origin main
git status --short
```

上記は現行 `main` での例です。別ブランチが指定された場合はそのブランチに合わせます。認証は環境に設定されたGit/CLI認証を使い、トークンをファイルやコマンド履歴へ埋め込みません。pushできなかった場合は、ローカルコミット済みかどうかと原因を報告します。デプロイ成功とGitHubへのpush成功は別々に確認してください。

4. テストを実行し、現在のスキルの手順でソースをコミット・push・パッケージ化する。
5. **Sites側へpushしたコミットSHA**と、その内容に一致する静的アーカイブを保存・デプロイへ渡す。GitHub側の別履歴のSHAを代用しない。

定義検証・既存ゲーム・SQLite APIはnpm test。ブラウザ検証はPLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- --workers=1。公開版を書き換える管理テストを含むため、専用DBを使用し順に実行する。生成物の同期後にnpm run buildし、build/.openai/hosting.json・build/server/index.js・build/drizzle/をパッケージ化する。Sitesソースへアプリだけでなくcontent/shared/server/db/drizzle/scripts/packageファイルとmanifestも同期する。

新しいmanifestは同じproject_idを保持し、static設定を外してD1を宣言する。所有者の認証済みメールはSitesのOWNER_EMAIL環境変数で設定し、値をソースへ埋め込まない。ローカルDBやwork/、生成Worker、認証情報はコミットしない。

今回の最終確認は、既存ゲームと管理/クラウドのPlaywright全34件、1440×900・390×844・320×568・844×390の追加12件が通過。Node側は既存ゲーム/コンテンツ検証に加えてSQLite API7ケースが通過。生成Workerからゲーム・管理画面・画像・定義JSONを配信できることも確認した。本番DB/Workerの反映結果は公開時に別途確認する。

公開アーカイブはnpm run package:siteでwork/site.tar.gzへ生成する。ルートに.openai/hosting.json、dist/server/index.js、drizzle/が必要。D1宣言は文字列"DB"。本番は4テーブルの作成と所有者限定を確認し、公開ゲームもPlaywrightでPC/スマホ幅を操作した。詳細と確認範囲はBACKEND.md参照。

## うんのよさと会心の一撃（2026-11-07）

うんのよさは旅団共通でLv.1に10、レベルごとに2上昇します。仲間の個別詳細・記録へ表示。物理ダメージスキル（現在は流星斬り）使用時に1回、`min(0.5, max(0, うんのよさ) / 512)` で会心を抽選します。Lv.5で約3.52%、Lv.30で約13.28%。通常攻撃・仲間の自動攻撃・敵攻撃・魔法・回復は対象外。会心時は「会心の一撃！」を結果メッセージとログへ表示します。

会心ダメージは `max(0, floor(攻撃力 × (0.9 + 0.2 × r) × スキル威力))`（rは0以上1未満）。守備力を無視し、攻撃力0・威力0なら0。通常時の物理式は維持。ドラクエの守備無視・攻撃力基準を参考にした独自調整で、特定作品の完全再現ではありません。

計算はdist/combat.jsのphysicalDamage、抽選と結果はshared/rules.jsのskillResult、表示はdist/party.js/game.jsに集約。成長設定はrules.growth.baseLuck/luckPerLevel（省略時10/2）で、旧公開定義・キャッシュ・戦闘中の定義にも適用します。不正な設定は共通バリデーターが拒否。公開済みDB定義は編集しません。保存キーとv:2を維持し、既存レベルから能力を算出するため進行データの書き換えは不要です。

検証はnpm testとtests/e2e/luck.spec.cjs。会心の確率境界・上限、守備無視、通常攻撃/魔法の対象外、MP消費、開始確認前のHP/MP保持、結果メッセージ、再読込の互換を確認します。PC幅・スマホ幅のスクリーンショットとコンソールも確認し、スマートフォン実機とは区別します。
