味方4人全員を操作します。各人の番に「こうげき・スキル・どうぐ・ぼうぎょ」を選び、どうぐから逃走も選べます。行動順は素早さ順。操作する人の状態欄を強調し、題名に名前を表示します。主人公が戦闘不能でも、生存する仲間の番に入力できます。スキルは使用者本人のMP・攻撃力・賢さ・うんのよさ、敵攻撃は対象本人の守備力を参照します。防御は本人だけに、その人の行動後からラウンド終了まで有効です。開始メッセージを送るまで能力・HP/MP・道具は変化しません。反映直前に使用者・対象・MPを再検証し、無効なら消費せず見送ります。

HP・MP・攻撃力・守備力・賢さ・素早さ・うんのよさと装備は個別です。レベル・経験値、習得レベル、資金・所持品は旅団共通です。「もちもの」の「操作する人物」で、非戦闘の回復スキル使用者と装備を変更する人を選びます。戦闘中は行動者に固定され、装備は変更できません。購入済み装備は全員が同じものを装着可能です。人物の選択はセーブしません。道具の対象選択は非戦闘では連続使用でき、戦闘では次の人の番になると解除します。

```text
content/game.json          初期定義（固定ID付き）
shared/                    定義/セーブ検証、純粋なゲーム計算
server/                    共通API・Node SQLite開発サーバー・本番Worker
 db/schema.ts              Drizzleスキーマ
 drizzle/                  SQLマイグレーションと生成メタデータ
 dist/                     既存フロント、bootstrap・cloud-save・admin/
 scripts/                  定義同期・検証・Workerビルド
 tests/                    定義、既存ゲーム、SQLite API、Playwright
 .openai/hosting.json       既存Site IDとD1バインディング
 build/                    生成Worker（Git対象外）
 .local/                   通常開発用SQLite（Git対象外）
 work/                     テストDB・一時検証（Git対象外）
```

Node.js 24以上。npm run devでフロントとSQLite APIを起動します。本番は同じAPIをWorkers/D1で実行。フロントは引き続きHTML/CSS/プレーンJS/SVGです。Reactへの書き換えはしていません。

bootstrap.jsが公開定義・キャッシュ・戦闘中の定義を選び、storage.js → combat.js → game.js → party.js → cloud-save.jsを順に起動します。dist/data.generated.js・dist/data/・dist/shared/は生成物で、content/とshared/を変更してnpm run content:syncします。

## 状態と保存

- 保存先はlocalStorageの **`starlight-rpg-v1`**。キーの名前はv1ですが、現在のデータ形式は **`v:2`** です。勝手に別キーへ切り替えると既存進行が見えなくなります。
- 保存するのは `state`。`tab`, `busy`, `sound`, AudioContextは実行時だけの状態で、保存しません。
- 攻撃力・守備力・賢さ・最大HP/MP・習得スキルは、レベルと装備から算出します。プレイヤーの賢さをセーブへ固定値で追加する必要はありません。
- v1/v2のセーブを受け入れ、旧位置をノードに変換し、素材辞書・最終訪問街・戦闘中の敵の賢さを補完します。
- `render()` は既定で保存も行います。`render(false)` だけは保存しません。リセット後に空の初期セーブを即再作成しないために必要です。
- リセットの確認を開いた段階では保存は変わりません。「OK」でゲーム専用キーを削除し、メモリ内を初期化して `render(false)`。次の通常操作、または再読み込み後の初回描画から自動保存を再開します。他アプリのlocalStorageは消しません。

主な `state` フィールド：

| フィールド | 用途 |
| --- | --- |
| `v`, `lv`, `xp`, `hp`, `mp`, `gold` | 形式バージョンと成長・現在値 |
| `weapon`, `armor`, `owned`, `items`, `materials` | 装備ID、所有装備、消耗品、素材の個数 |
| `node`, `zone`, `village`, `lastTown` | 現在ノード、エリア、街判定、復帰先 |
| `kills`, `cleared` | エリアごとの討伐数とボス撃破フラグ（各3要素） |
| `total`, `claimed` | 累計討伐と一度限りの討伐依頼報酬 |
| `enemy`, `turn`, `log` | 戦闘中の敵、ターン、冒険ログ（最大35件） |

## 戦闘の流れ

1. `startBattle` が現在エリアの敵、またはボスを生成。
2. `combat('attack')` は物理計算を行う。`useSkill` は種別ごとの計算を行ってから `combat('skill')` へ進む。アイテムも使用後に敵ターンへ進む。
3. `busy` を立てて入力を抑止し、描画・保存。敵HPが0なら即 `win` して敵の反撃はなし。
4. 約430ms後、敵の物理攻撃を解決。3ターンごとに強攻撃。防御を選んだターンは軽減倍率を適用。
5. 全滅なら所持金の15%（切り捨て）を失い、`lastTown` へ戻りHP/MP全回復。進行・装備は維持。
6. `busy` を解除して描画・保存。

敵攻撃にもプレイヤーと同じ物理計算を使います。敵にも賢さはありますが、現在は敵の魔法行動は実装していません。

## 4人対4体の戦闘（2026-11-05）

保存キーとv:2は維持。companions/enemiesを追加し、旧セーブは仲間3人を全回復で追加、戦闘中の旧敵は1体の隊列として継続します。ラウンド中の再読込は直前の確定ラウンドから再開（途中経過は保存しない）。戦闘中の定義スナップショットは維持します。

うんのよさはキャラクターごとの個別成長設定を使用します。アステルはLv.1に10、レベルごとに2上昇します。仲間の個別詳細・記録へ表示。物理ダメージスキル（現在は流星斬り）使用時に1回、`min(0.5, max(0, うんのよさ) / 512)` で会心を抽選します。Lv.5で約3.52%、Lv.30で約13.28%。通常攻撃・敵攻撃・魔法・回復は対象外。会心時は「会心の一撃！」を結果メッセージとログへ表示します。

会心ダメージは `max(0, floor(攻撃力 × (0.9 + 0.2 × r) × スキル威力))`（rは0以上1未満）。守備力を無視し、攻撃力0・威力0なら0。通常時の物理式は維持。ドラクエの守備無視・攻撃力基準を参考にした独自調整で、特定作品の完全再現ではありません。

計算はdist/combat.jsのphysicalDamage、抽選と結果はshared/rules.jsのskillResult、表示はdist/party.js/game.jsに集約。成長設定はrules.growth.baseLuck/luckPerLevel（省略時10/2）で、旧公開定義・キャッシュ・戦闘中の定義にも適用します。不正な設定は共通バリデーターが拒否。公開済みDB定義は編集しません。保存キーとv:2を維持し、既存レベルから能力を算出するため進行データの書き換えは不要です。

検証はnpm testとtests/e2e/luck.spec.cjs。会心の確率境界・上限、守備無視、通常攻撃/魔法の対象外、MP消費、開始確認前のHP/MP保持、結果メッセージ、再読込の互換を確認します。PC幅・スマホ幅のスクリーンショットとコンソールも確認し、スマートフォン実機とは区別します。

## 攻撃力上昇バフと特技「鼓舞」（2026-11-09）

Lv.2で「鼓舞」を習得します（MP4・戦闘専用）。スキル一覧から選び、生存中の味方1人をクリックすると、行動開始メッセージの確認後に攻撃力が1.5倍になります。自分にも使え、HP満タンでも対象にできます。対象者の通常攻撃・物理ダメージ特技とその会心に適用し、魔法・回復・敵や他の味方の攻撃には影響しません。実効攻撃力は基本攻撃力×倍率を切り捨てた値です。

継続は残り3ターン。全員の行動が終わるターン終了時に1減り、付与したターンでは減りません。同種の効果は重ならず、再使用で残り3ターンへ更新します。0になると解除し、戦闘不能・勝利・逃走・全滅でも解除します。次の戦闘へは持ち越しません。

効果中の味方は画像上辺の小さな「剣↑」アイコンと残数で確認できます。状態欄のポップアップと「仲間」の個別詳細には、バフ名・攻撃力倍率・残りターンを表示し、攻撃力欄も補正後の値になります。通常の詳細を開けるタイミングとメッセージ送りは従来どおりです。道具・回復スキル・鼓舞の対象選択中は、味方クリックを対象指定に使います。

バフとMPは行動開始メッセージを送るまで変化せず、反映直前に対象とMPを再確認します。対象が戦闘不能になった場合などはMPを消費せず見送ります。戻る・Esc・非戦闘使用・MP不足も消費なし。ターン境界の既存自動保存へ効果と残数を含め、戦闘中の再読み込みは従来と同じ確定済みターンから再開します。古いセーブはバフなしとして読み込み、進行を消去しません。

実装の入口：shared/rules.jsのactiveBuffs/allyAttack/applyAttackBuff/tickBuffs/normalizeBuffs/validateBuffs。state.buffsは省略可の配列（characterId/skillId/remainingTurns/appliedTurn）で、効果と名前は戦闘定義から参照します。party.jsが物理攻撃にallyAttack(i)を渡し、tickBuffsはターン末・turn加算前に一度だけ呼びます。表示はbuffIcons/buffDetails、詳細カードは仲間画面と共通。game.jsの起動時とpartyの描画で不正/非戦闘のバフを除去。セーブv:2・キーは維持。公開定義が変わってもSaveRulesは検証済みbattleContentのスキルでバフを検証します。

## 補正後の攻撃力の色（2026-11-09）

キャラクター画像から開くポップアップと仲間の個別詳細では、補正後の攻撃力を表示します。レベルと装備から算出した基本攻撃力と比べ、上昇中は青、下降中は赤、同じなら通常の文字色です。バフ解除後は基本値と通常色に戻ります。数字の読み上げとツールチップにも実効値・基本値・増減方向を示します。HP/MPの消費は能力下降として色分けしません。攻撃下降の特技自体はまだ追加していません。
