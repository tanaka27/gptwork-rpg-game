# 装備の抽選での不正な乱数の検出

- 状態：反映完了（GitHubのみ、Sites未反映）
- 設計版：v1
- 要求・背景：レアリティ5段階化の作業中に、テストで用意した乱数が尽きると追加効果がNaNになり、読み込み時に何も知らせずに標準品へ戻ることが分かった。不正な値はその場でエラーにする（ユーザー要望）。
- 設計作成者：Claude Code

## 目的・受け入れ条件
- 装備の抽選に使う乱数が0以上1未満の数値でなければ、すぐにエラーにする（undefined・NaN・1以上・負数・Infinity・文字列）。
- エラーのとき、所持品・通し番号・ログ・星のしずくを変えない。
- 通常のゲーム（`Math.random`）の挙動は変えない。

## 原因
- `rollGear` は `rng()` の戻り値を確かめずに計算していた。`undefined` は計算でNaNになり、`Math.max(1, NaN)` もNaNのため、追加効果がNaNの個体ができた。
- 読み込み時の正規化は、検証を通らない個体を標準品に戻す。このため、テストの乱数が足りないと「なぜかコモンになる」結果だけが残り、原因が見えなかった。
- `rollEquipmentDrop` の13%判定は `undefined >= 0.13` が false になるため、乱数がないときに「ドロップあり」と判定していた。

## 実装設計
- `GameRules.drawRandom(rng)`：値を確かめて返し、不正なら `RangeError`（「抽選の乱数は0以上1未満の数値が必要です: 値」）。
- `rollGear` のレアリティ・能力・倍率の3か所と、`rollEquipmentDrop` の13%判定・候補の2か所で使う。`addGear` は個体を作る前に抽選するので、エラー時は何も変わらない。
- 読み込み時の正規化（壊れた個体を標準品へ戻す）は、保存データの保護のため従来どおり。
- 互換性：セーブ・定義の形式は変更なし。

## 検証計画
- ロジック：6種類の不正な値、4つ目の数値で尽きる場合、上限ぎりぎりの正常値、ドロップでのエラーと状態の不変。
- E2E：装備・戦闘の関連spec、全E2E。
