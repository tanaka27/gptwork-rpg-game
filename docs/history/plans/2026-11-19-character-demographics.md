# キャラクターの年齢・性別表示

- 状態：反映完了
- 設計版：v1
- 要求・背景：固定キャラクターと酒場の画像付き冒険者すべてに年齢・性別を持たせ、人物詳細の名前の直下へ表示する。既存画像を見て架空人物の年齢を設定する。
- 設計作成者（子）：`/root/character_demographics`

## 目的・受け入れ条件
- 初期仲間4人と酒場の冒険者100人に年齢・性別があり、正規データ上で一意に読める。
- 仲間詳細（戦闘中のステータス詳細を含む）と酒場冒険者詳細で、名前のすぐ下に `21歳 · 男性` 形式で表示する。
- 旧 `v:1` / `v:2` セーブ、進行中の戦闘snapshot、旧公開定義が読み込め、所持品・討伐数・NPC位置などの進行を保持する。
- 不正な新規定義は共通コンテンツ検証で拒否する。既存の有効な明示値は互換補完で上書きしない。

## 対象範囲
- 変更するファイル・機能：`content/game.json`、`shared/adventurers.js`、`shared/content.js`、`dist/party.js`、`dist/game.js`、`dist/workspace.css`。同期生成物は `npm run content:sync` で更新する。関連するロジック・E2Eと `GAME_SPEC.md`、`DESIGN.md`、`BACKEND.md`、`CHARACTER_ART.md`、`CHANGELOG.md` を更新する。
- 影響する既存仕様・関連文書：固定ID、NPC位置だけを保存する仕様、`withJobs` の旧定義補完、仲間詳細と酒場NPC詳細の表示仕様。
- 対象外：画像の再生成、ID・セーブ形式・DB schemaの変更、NPCの位置・能力計算の変更。

## 実装設計
- 変更内容（処理・画面・データ・API）：人物属性は `age`（整数、0〜120）と `gender`（`男性` / `女性` / `その他` / `未設定`）とする。初期4人は画像・既存の人物指定に基づき、アステル21歳男性、リナ20歳女性、ガルド35歳男性、ノエル21歳男性を初期案とする。NPC100人はID付き画像を全数確認したうえで、IDごとに年齢を推定し、性別は既存名と画像の人物表現に整合させて固定値を設定する。人物属性は `content/game.json` と `shared/adventurers.js` を正本とし、NPC生成にも各IDの値を付与する。`shared/content.js` は年齢の整数範囲と性別enumを検証する。名前下の二次情報として、仲間詳細カードと酒場NPC詳細に属性を表示する。
- 既存セーブ・公開済み定義との互換性と移行：セーブ形式 `v:1` / `v:2` は変えず、新しいセーブ項目を追加しない。`GameContent.withJobs` の非破壊互換補完に、demographics未指定の旧キャラクターへ既定値を加える処理を足し、`age` と `gender` の有効な明示値は保持する。明示された不正値は検証エラーとする。旧4人は同梱既定値、未知の旧定義キャラクターは互換用の年齢18・性別「未設定」を補う。保存済みの `battleContent` も同じ経路で表示可能にする。NPC属性は名簿から導出し、セーブされる位置構造に触れないため、DB・セーブschemaの移行は不要。既存進行を使った読み込み検証で非破壊を確認する。
- 異常系・リスクと対策：古い公開定義や戦闘snapshotは表示前に補完する。既存の有効値は維持し、明示的な不正値を既定値で隠さず拒否する。NPCは全100 IDに値があることをテストで検証する。画像と年齢は近似なので、年齢範囲は成人に固定せず見た目に沿って個別設定する。

## 検証計画
- 受け入れ条件ごとの確認方法（ロジック/API/Playwright）：content validatorの正常/異常値、100人全員の属性存在・型・範囲、旧定義および旧battleContentの互換補完、v1/v2セーブの進行保持をロジック/APIテストで確認する。`content:sync` 後、仲間詳細と酒場NPC詳細をPC幅・スマホ幅の両方でPlaywright E2E実行し、名前直下の表示、操作後状態、console/pageerrorを確認する。各幅の画面を撮影して目視する。
- 対象外の検証と理由：キャラクター画像を変更しないため画像生成・画像配信の再検証は不要。iOS/Android実機は今回のブラウザ幅検証の対象外。
- 反映・復旧方法：親がレビュー後にcommit/push・Sites反映する。復旧は本変更のcommitをrevertし、`npm run content:sync` と関連テストを再実行する。永続セーブ・DB形式を変更しないため、利用者データの逆移行は不要。
