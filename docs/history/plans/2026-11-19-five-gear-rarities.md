# 装備レアリティの5段階化（エピックの追加）

- 状態：反映完了（GitHubのみ、Sites未反映）
- 設計版：v1
- 要求・背景：装備のレアリティにエピックを加えて5段階（コモン50%・アンコモン30%・レア12.5%・エピック5%・レジェンダリー2.5%）にし、追加効果の数と強さも合わせて増やす（ユーザー要望）。
- 設計作成者：Claude Code

## 目的・受け入れ条件
- ドロップ装備の抽選が5段階の確率になり、追加効果はコモン0・アンコモン1・レア2・エピック3・レジェンダリー4つになる。
- 倍率の幅を全体に引き上げる：アンコモン0.6〜0.9、レア0.8〜1.1、エピック1.0〜1.3、レジェンダリー1.2〜1.6。
- エピックを一覧・詳細・キャラクター詳細・ログ・並べ替え・売却・管理画面で扱える。
- 旧4段階のセーブ・公開定義・クラウドセーブを壊さない。

## 実装設計
- `shared/content.js`：レアリティIDに `epic`。抽選ルールの検証は5段階の確率・4段階の倍率の幅・候補の能力4種類以上（レジェンダリーで4つ選ぶため）。定義のレジェンダリーは固有装備と旧定義のため追加効果3つも可。ショップにエピックは置けない。エピックのない4段階の `rules.gearRoll` は clone 上で外し、`withJobs` が同梱定義の5段階ルールを補う。廃止した旧ID `epic`（追加効果2つ）は今のレアへ読み替え、新しいエピック（3つ）はそのまま。
- `shared/rules.js`：5段階の抽選（累積確率は浮動小数点の誤差を丸めて境界を判定）、個数、売却倍率（エピック3.5）。読み込み時の正規化 `migrateGearInstance`：抽選品のレジェンダリー（3つ）はエピックに、形の正しい抽選品の数値は今の範囲へ最も近い値に収める（標準品・固有装備は対象外）。
- `shared/save.js`：`prepareForLoad`（複製へ正規化を適用）。`dist/cloud-save.js` の復元で検証前に使う。
- 画面：エピックは桃色（枠 `#df74b4`、文字 `#ee8fc6`、淡い光彩）。レアリティ順はレジェンダリー→エピック→レア。ヘルプの説明を5段階に。管理画面に確率・倍率の幅・プレビュー列を追加。
- 互換性：保存キー・形式（`v:2`）は変更なし。サーバーの保存・公開時検証は正規化しないため、旧ルールのクラウドセーブは保存し直すまで新しい定義の公開を拒否させる（BACKEND.mdに記載）。

## 検証計画
- ロジック：境界・個数・範囲・分布・旧ルールと旧個体の移行・定義の検証・売却額。
- E2E：エピックのドロップと表示色・並べ替え、旧レジェンダリーの読み込み移行、旧クラウドセーブの復元、管理画面の5段階編集。全E2EをPC/スマホ相当幅で実行。
