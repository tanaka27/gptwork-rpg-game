# 仲間のコマンド操作と個別能力

- 状態：反映完了
- 設計版：v1
- 要求：仲間も主人公と同じように操作し、各自のステータスを持つ。
- 設計作成者：/root

## 目的・受け入れ条件
- 生存する全味方の素早さ順の番で入力を待ち、通常攻撃・スキル・道具・防御・逃走を選べる。戦闘不能者は飛ばす。主人公が倒れても仲間を操作できる。
- 各自のHP/MP上限、攻撃・守備・賢さ・素早さ・運、装備を計算・表示・戦闘に使う。レベル・経験値は従来どおり旅団共通と明示し、スキル習得レベルも共通。所持品・資金も共通。
- 操作中の人物を強調し、コマンド題名へ名前を表示。フィールド外ではもちもの上の人物選択で装備・回復スキルの使用者を切替できる。
- 旧セーブ・クラウド保存・公開済み定義を保持し、進行を消去しない。

## 実装設計
- shared/rules.js: stats(state,data,index=0)を個別化。characters[].statsに任意の成長設定（baseHP/hpPerLevel等の12項目）を追加し、共通growthへ上書きして算出。既存公開版にはID別の既定プロファイルを適用し、未知IDは共通growthを使う。主人公は従来値。リナはHP64/成長14、MP24/5、攻撃12/3、守備6/2、賢さ14/5、運14/3。ガルドはHP100/20、MP12/2、攻撃18/5、守備12/3、賢さ6/2、運8/1。ノエルはHP68/14、MP32/6、攻撃10/3、守備7/2、賢さ18/6、運12/2。素早さは既存character.speed+旅団lv-1。
- 能力は各人の定義・共通レベル・個別装備から導出し、実数の固定コピーを保存しない。主人公の既存トップレベル装備/HP/MPを維持。companionsへweapon/armorを追加、未設定は移行時の主人公装備を継承。装備は従来の購入済みアンロック方式で全員が同じIDを同時に装着可能。
- 旧仲間の現在HP/MPは新上限を超えても移行時に切り捨てず保持。回復で減らさず、消費/被ダメージで自然に上限以下へ戻る。新規/不足メンバーは本人の最大値で初期化。ID照合、旧配列順フォールバックを維持。
- party.js: actingAlly（実行時のみ、非戦闘では選択人物）でコマンドの使用者を管理。executePartyRoundは各生存味方でgetCommand(index)を呼び、actorごとにkind/skillをリセット。入力と反映直前に使用者の生存/MP/習得/対象を検証。MPは使用者だけ、回復上限と守備は対象本人、防御はSetで各自を記録してそのラウンド終了まで有効。道具選択・スキル選択は使用者の番が変わると解除し、同一人物の次の番まで持ち越さない。
- 各人の表示・バフ基本攻撃値・回復アイテム（割合全回復含む）・回復魔法・守備・宿屋/救助/レベルアップ/ボス回復を個別上限へ統一。宿代不足は各自の現在値を保持し最低半分まで回復。
- 非戦闘の人物選択はもちもの内のselect。戦闘中は実際の行動者へ固定しselect無効。装備は非戦闘だけ変更可能。詳細に装備名と共通レベルを表示。
- shared/content.jsで任意の個別成長設定を範囲検証。shared/save.jsで任意の仲間装備ID/型/所持、characterIdの重複/不正を検証。既存v1/v2受入とキー/v:2は維持。battleContentを個別装備の検証でも優先。
- content/game.jsonへ既定プロファイルを明示（既存公開DBは変更しない）、管理画面のキャラクター編集でもstatsを扱う。生成物はcontent:syncで更新。
- README、仕様、引き継ぎ、開発手順、CHANGELOG、ヘルプと配信キャッシュを更新。

## 検証計画
- npm test: 既存の自動攻撃前提テストはテスト用コマンド供給を調整（主人公に指定コマンド、仲間は通常攻撃）し、実制御は専用ケースとE2Eで検証。
- 個別成長/装備/バフの独立、旧セーブ・上限超過・ID照合・不正装備・旧定義、回復上限・宿泊・成長回復をロジック検証。
- Playwright PC1440x900/スマホ幅390x844: リナ→ノエル→主人公→ガルドの入力停止、仲間スキルMP・対象回復・道具・防御、主人公死亡時の操作、戻る/Esc/二重入力、装備人物切替と保存再読込、ステータスとスクリーンショット・コンソール・寸法を確認。既存E2Eを現仕様へ更新し回帰検証。
- スマホ実機・音声・全編の長時間バランスは対象外。
- 検証後GitHub mainへpushし既存Site（所有者限定）へ同じWorkerをデプロイ。問題時は以前の版へ復旧可能。既存DB公開定義は変更しない。
