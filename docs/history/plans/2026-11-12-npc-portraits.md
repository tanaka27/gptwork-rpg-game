# 酒場の冒険者ポートレート100人

- 状態：反映完了
- 設計版：v2
- 要求・背景：既存4人の絵を保ち、酒場の冒険者100人に専用画像を追加する。生成原画は全身、一覧では胸上の正方形クロップで見せる。
- 設計作成者（子）：Codex 子エージェント

## 目的・受け入れ条件

- 現在のロスター固定ID adventurer_001〜adventurer_100 それぞれに固有画像を1枚割り当てる。IDは shared/adventurers.js の既存定義と一致させ、保存形式・位置・能力は変えない。
- 1024×1536 の全身原画を人物ごとに生成し、512×768 WebP に縮小して配信する。既存4人 astel / rina / gald / noel の原画・画素は維持する。
- 酒場一覧の正方形画像は全身原画の頭頂から胸上を明瞭に見せる。酒場のNPC冒険者詳細では全身画像を表示する。
- 酒場の冒険者一覧に名前・職業・レベルと画像を表示し、100人でもヘッダー、タブ、一覧操作を保つ。閉じる操作とタブ移動がキーボード、支援技術で分かる。
- 画像、アプリコード、Worker を同梱した最終成果物をPC・モバイル幅で確認し、Worker gzip が10 MiB未満であることを確認する。

## 対象範囲

- 変更するファイル・機能：
  - 画像：dist/assets/characters/adventurer_001.webp 〜 dist/assets/characters/adventurer_100.webp。IDとファイル名は接尾辞を含め一対一で対応する（例：adventurer_001 → adventurer_001.webp）。生成原画はwork/npc100-originals/、縮小済みWebPはwork/npc100-delivery/に保管する。両方ともv2コード承認まではdistへ移さず、コミットしない。
  - 酒場一覧・詳細・操作：dist/index.html、dist/game.js、dist/workspace.css。
  - 画像生成・配信仕様：docs/CHARACTER_ART.md、docs/DESIGN.md。Worker MIME・ビルドが変わる場合は scripts/build.cjs、server/worker.mjs、server/dev.mjs、開発手順、関連E2Eを更新する。
- 影響する既存仕様・関連文書：固定IDは shared/adventurers.js の定義に合わせる。表示規約は docs/CHARACTER_ART.md と docs/DESIGN.md を正本とする。
- 対象外：仲間の出現・移動・能力・セーブ、初期4人の絵、酒場依頼、画面全体のレイアウト変更、DB/API。未知IDへ既存画像を流用しない。

## 実装設計

### 生成と配信

- 共通画風：オリジナルの日本2DアニメRPG立ち絵、明瞭な線、セル塗り、月夜の抑えた宝石色。単色の暗い青緑背景 #203638。風景、文字、UI、枠、透かし、既存キャラの模倣を含めない。
- 1 ID 1人物、全身を正面寄りに立たせ、頭頂・両手・靴先を画面内に残す。顔立ち、髪型、肌色、体格、装身具を100人で変え、10職業の装いは役割ごとに読み分けられるようにする。同じ職業でも人物の顔・色・シルエットを重複させない。武器・道具は職業を示す補助とし、顔を隠さない。
- 画像生成ツールの戻り値は画像の data URL（image_url）なので、原画を work/npc100-originals/ID.png に保存してから加工する。1024×1536 原画を高品質縮小し、512×768 WebP quality 78 を目安にする。平均35 KiB以下を目標とし、100枚合計3.5 MiB以下・1枚50 KiB以下を受け入れ上限として再圧縮する。画面での見え方を確認してから採用する。縮小済みWebPはwork/npc100-delivery/でレビューし、v2コード承認後にだけdistへ配置する。
- 一覧用の固定正方形ラッパーは overflow:hidden とし、object-fit:cover だけに頼らない。512×768画像を横幅240%（2.4倍）、高さ自動で配置する。初期クロップの焦点は原画の x=50%、y=12% なので、ラッパー基準の画像位置は x=-70%、y=6.8%（元画像比で上部約28%が表示範囲）。拡大率と焦点位置は画像IDごとにCSS変数で調整できるようにする。原画の頭部は上端から4〜15%、胸上は約28%以内に収まるよう生成する。酒場のNPC冒険者詳細では同じWebPをobject-fit:containで全身表示し、縦スクロール内に能力値を残す。初期4人の仲間一覧・詳細表示は対象外。
- 一覧画像は width/height 属性、loading=lazy、decoding=async を指定し、画面に入った分だけ取得する。読み込み失敗時も名前・職業・レベルと選択操作は使える。画像altは空（装飾）とし、ボタンのaria-labelで名前・職業・レベル・詳細操作を伝える。
- 画像配信：既存PNGの原本とdistファイルは変更しない。scripts/build.cjsでPNGバイトをImageMagickのlossless WebPへ変換し、既存の .png URL のままWorkerへ格納する。Worker応答はContent-Type: image/webpとし、PNG URLを含む既存の全画像URLを維持する。変換はビルド時だけ行い、server/dev.mjsは既存PNGをimage/pngのまま配信する。新規の .webp はWorkerとserver/dev.mjsの両方でimage/webpとして扱い、バイナリをBase64で同梱する。Workerの画像キャッシュは既存の300秒をimage/webpにも適用する。
- ビルド依存：ImageMagick 7系でWebP delegateを有効にする。scripts/build.cjsは起動時にconvertとWebP対応を確認し、無ければ不足条件を明記して失敗する。別形式・未圧縮PNGへのフォールバックは行わない。docs/DEVELOPMENT.mdにインストール要件を記載する。
- 容量の受け入れ条件：現在のWorkerはgzip 8,956,759 bytes。既存6 PNGをscratchでlossless WebPにした実測では画像Base64+gzipが8,869,556から5,901,770 bytesに減り、画素差分は全て0だった。100枚の新規WebPは合計3.5 MiB以下・1枚50 KiB以下とする。この値でのWorker gzip予測は約9.57 MBだが、最終ビルドの実測を優先する。build.cjsはWorkerをgzip level 9で計測し、10 MiB（10,485,760 bytes）以上なら失敗する。条件を満たさない場合は公開せず、画像圧縮または配信設計を再検討する。

### 酒場UI

- 変更は酒場パネル内に限定する。酒場の冒険者・依頼タブを冒険者一覧の左側に縦配置する。狭幅でも左サイドバーを維持し、幅約64〜76px、ボタン高44pxを確保する。冒険者行は高さ約96〜100px、一覧画像はPC 80〜88px、狭幅72pxを目安にする。
- 一覧部分だけを内側スクロール領域にし、酒場見出し、タブ、一覧件数は固定する。2〜3行が見える高さを優先し、既存のcommand panel内に納める。
- 下部の「街のコマンドへ戻る」ボタンを酒場パネル右上の「×」に置換する。×は44×44px以上、aria-label「酒場を閉じる」、明瞭なfocus-visible表示を付ける。閉じると既存酒場コマンドへフォーカスを戻す。
- 冒険者詳細では画像全身と現在の能力値を表示する。戻る操作後は選択した一覧行へフォーカスを戻す。依頼タブと受注・報告の挙動は維持する。

### 互換性・異常系

- 画像は固定IDからのみ引く。astel / rina / gald / noel は同じPNG URLを維持し、Workerでは画素同一のlossless WebP応答とする。adventurer_001〜100 は新規WebPを使う。未知ID・欠損画像で別人の画像へフォールバックしない。
- セーブ形式、ロスター定義、DB、公開定義は変更しない。画像が404でもリスト操作・詳細テキストは機能する。
- 画像追加後もWorkerの全資産を埋め込む方式を使うため、生成画像の容量と最終gzipサイズをリリース前に検証する。
