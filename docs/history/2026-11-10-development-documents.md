### 状態と保存

- 保存先はlocalStorageの **`starlight-rpg-v1`**。キーの名前はv1ですが、現在のデータ形式は **`v:2`** です。勝手に別キーへ切り替えると既存進行が見えなくなります。
- 保存するのは `state`。`tab`, `busy`, `sound`, AudioContextは実行時だけの状態で、保存しません。
- 攻撃力・守備力・賢さ・最大HP/MP・習得スキルは、レベルと装備から算出します。プレイヤーの賢さをセーブへ固定値で追加する必要はありません。
- v1/v2のセーブを受け入れ、旧位置をノードに変換し、素材辞書・最終訪問街・戦闘中の敵の賢さを補完します。
- `render()` は既定で保存も行います。`render(false)` だけは保存しません。リセット後に空の初期セーブを即再作成しないために必要です。
- リセットの確認を開いた段階では保存は変わりません。「OK」でゲーム専用キーを削除し、メモリ内を初期化して `render(false)`。次の通常操作、または再読み込み後の初回描画から自動保存を再開します。他アプリのlocalStorageは消しません。

主な `state` フィールド：

| フィールド | 用途 |
| --- | --- |
| `v`, `lv`, `xp`, `hp`, `mp`, `gold` | 形式バージョンと成長・現在値 |
| `weapon`, `armor`, `owned`, `items`, `materials` | 装備ID、所有装備、消耗品、素材の個数 |
| `node`, `zone`, `village`, `lastTown` | 現在ノード、エリア、街判定、復帰先 |
| `kills`, `cleared` | エリアごとの討伐数とボス撃破フラグ（各3要素） |
| `total`, `claimed` | 累計討伐と一度限りの討伐依頼報酬 |
| `enemy`, `turn`, `log` | 戦闘中の敵、ターン、冒険ログ（最大35件） |

### 戦闘の流れ

1. `startBattle` が現在エリアの敵、またはボスを生成。
2. `combat('attack')` は物理計算を行う。`useSkill` は種別ごとの計算を行ってから `combat('skill')` へ進む。アイテムも使用後に敵ターンへ進む。
3. `busy` を立てて入力を抑止し、描画・保存。敵HPが0なら即 `win` して敵の反撃はなし。
4. 約430ms後、敵の物理攻撃を解決。3ターンごとに強攻撃。防御を選んだターンは軽減倍率を適用。
5. 全滅なら所持金の15%（切り捨て）を失い、`lastTown` へ戻りHP/MP全回復。進行・装備は維持。
6. `busy` を解除して描画・保存。

敵攻撃にもプレイヤーと同じ物理計算を使います。敵にも賢さはありますが、現在は敵の魔法行動は実装していません。

### うんのよさと会心の一撃（2026-11-07）

うんのよさはキャラクターごとの個別成長設定を使用します。アステルはLv.1に10、レベルごとに2上昇します。仲間の個別詳細・記録へ表示。物理ダメージスキル（現在は流星斬り）使用時に1回、`min(0.5, max(0, うんのよさ) / 512)` で会心を抽選します。Lv.5で約3.52%、Lv.30で約13.28%。通常攻撃・敵攻撃・魔法・回復は対象外。会心時は「会心の一撃！」を結果メッセージとログへ表示します。

会心ダメージは `max(0, floor(攻撃力 × (0.9 + 0.2 × r) × スキル威力))`（rは0以上1未満）。守備力を無視し、攻撃力0・威力0なら0。通常時の物理式は維持。ドラクエの守備無視・攻撃力基準を参考にした独自調整で、特定作品の完全再現ではありません。

計算はdist/combat.jsのphysicalDamage、抽選と結果はshared/rules.jsのskillResult、表示はdist/party.js/game.jsに集約。成長設定はrules.growth.baseLuck/luckPerLevel（省略時10/2）で、旧公開定義・キャッシュ・戦闘中の定義にも適用します。不正な設定は共通バリデーターが拒否。公開済みDB定義は編集しません。保存キーとv:2を維持し、既存レベルから能力を算出するため進行データの書き換えは不要です。

検証はnpm testとtests/e2e/luck.spec.cjs。会心の確率境界・上限、守備無視、通常攻撃/魔法の対象外、MP消費、開始確認前のHP/MP保持、結果メッセージ、再読込の互換を確認します。PC幅・スマホ幅のスクリーンショットとコンソールも確認し、スマートフォン実機とは区別します。

継続は残り3ターン。全員の行動が終わるターン終了時に1減り、付与したターンでは減りません。同種の効果は重ならず、再使用で残り3ターンへ更新します。0になると解除し、戦闘不能・勝利・逃走・全滅でも解除します。次の戦闘へは持ち越しません。

バフとMPは行動開始メッセージを送るまで変化せず、反映直前に対象とMPを再確認します。対象が戦闘不能になった場合などはMPを消費せず見送ります。戻る・Esc・非戦闘使用・MP不足も消費なし。ターン境界の既存自動保存へ効果と残数を含め、戦闘中の再読み込みは従来と同じ確定済みターンから再開します。古いセーブはバフなしとして読み込み、進行を消去しません。

実装の入口：shared/rules.jsのactiveBuffs/allyAttack/applyAttackBuff/tickBuffs/normalizeBuffs/validateBuffs。state.buffsは省略可の配列（characterId/skillId/remainingTurns/appliedTurn）で、効果と名前は戦闘定義から参照します。party.jsが物理攻撃にallyAttack(i)を渡し、tickBuffsはターン末・turn加算前に一度だけ呼びます。表示はbuffIcons/buffDetails、詳細カードは仲間画面と共通。game.jsの起動時とpartyの描画で不正/非戦闘のバフを除去。セーブv:2・キーは維持。公開定義が変わってもSaveRulesは検証済みbattleContentのスキルでバフを検証します。

### 補正後の攻撃力の色（2026-11-09）

キャラクター画像から開くポップアップと仲間の個別詳細では、補正後の攻撃力を表示します。レベルと装備から算出した基本攻撃力と比べ、上昇中は青、下降中は赤、同じなら通常の文字色です。バフ解除後は基本値と通常色に戻ります。数字の読み上げとツールチップにも実効値・基本値・増減方向を示します。HP/MPの消費は能力下降として色分けしません。攻撃下降の特技自体はまだ追加していません。

### エージェントの役割と作業順

- 親エージェントは設計書と実装結果をレビュー・承認し、必要なら独立検証やテストを行います。親は実装コードを直接書かず、修正点を子へ返して子に直させます。
- 調査・設計書作成・実装・テスト・必要な文書更新はサブエージェント（子）が担当します。親が子を起動するときは `fork_turns=none`、`model=gpt-6-luna`、`reasoning_effort=max` を明示し、要求・範囲・関連仕様・受け入れ条件・制約など必要なコンテキストをspawn時に渡します。文書更新も同じ指定を使います。
- 指定モデルまたはeffortを使えない場合、別モデル・effortへ切り替えず阻害要因を報告します。ユーザーへの設計・実装レビューの都度確認は不要です。

- 文書のみの整備は設計承認ゲートの対象外です。子が更新・リンク整合を確認し、親がレビューした後、親がpush・Sites反映を行います。

## データ中心のRPG基盤

利用者1人を想定。既存のHTML/CSS/JSの画面と戦闘のクリック送りを維持し、定義・計算・保存を分離する。

### 正本と構成

- `content/game.json`：初期定義。全レコードに固定ID。初回DB未公開時と静的配信のフォールバック。
- `shared/content.js`：ID重複、参照、双方向接続、数値、効果、HTML混入の検証と旧UI向け変換。
- `shared/rules.js`：能力・敵生成・ドロップ・道中抽選・効果量の純粋関数。乱数を注入して検証可能。
- `shared/save.js`：クラウドへ取り込むセーブの検証。
- `dist/game.js`, `dist/party.js`：入力・画面・行動の進行制御。ゲーム処理の全部をサーバーへ移すものではない。
- `server/api.mjs`：定義・公開版・セーブAPI。ローカル/本番で同じコード。
- `server/local-db.mjs`：Node.js 24のSQLiteをD1と同じインターフェースで使用。
- `server/worker.mjs`：本番Worker。ESMスターターの構成を拡張し、静的素材もWorker内へ埋め込む。
- `dist/admin/`：所有者向け定義編集。個別のフォーム、参照先の選択、効果の編集、検索、複製、削除検証。
- `db/schema.ts`, `drizzle/`：Drizzleのスキーマと生成済みSQL/メタデータ。

DB公開後は、公開版がゲーム定義の正本になる。JSONは初期値またはエクスポート/インポート用で、GitのJSON編集がDB公開版を上書きすることはない。ソース変更時はcontent:syncで生成物を揃える。

### DB

| テーブル | 用途 |
| --- | --- |
| content_versions | 定義全体のスナップショット。下書きはrevisionで競合検出、公開後は不変 |
| app_settings | 現在の公開版ID |
| saves | 所有者の進行JSONと更新番号 |
| save_history | 更新前のクラウドセーブ。不変のバックアップ |

定義は関連をIDで表すJSON集約として保存する。定義ごとのテーブルへの分割は今後の検索要件に応じて実施できる。公開の切替はDB batchで処理し、現在のクラウドセーブが参照するデータを無効にする公開を拒否する。

### 認証・API

本番はSitesが注入するoai-authenticated-user-idと、環境変数OWNER_ID（サイト内認証ID）またはOWNER_EMAIL（認証済みメール）を照合する。APIは匿名・他人を拒否し、書き込みは同一Originも確認する。サービスアクセス用トークンは利用者IDの代わりにしない。認証情報をブラウザへ渡さない。

ローカル開発サーバーだけは127.0.0.1に限定しlocal-ownerを注入する。本番Workerにこの処理を含めない。

- GET /api/content：公開版（初回は同梱定義）
- GET /api/admin/versions：版一覧
- POST /api/admin/drafts：公開版の複製またはJSON取り込み
- GET/PUT /api/admin/versions/:id：取得・下書き更新
- POST /api/admin/versions/:id/validate：検証
- POST /api/admin/versions/:id/publish：公開/旧版への切替
- GET /api/admin/preview?version=:id：プレビュー用定義
- GET /api/admin/export：公開JSON
- GET/PUT /api/save：取得/明示的な保存。PUTはrevisionの一致が必要
- GET /api/save/history と /api/save/history/:id：バックアップ一覧/内容

クラウドは手動バックアップ・復元。ブラウザの自動保存は維持する。同じ更新番号による再送/競合は409となり、二重適用しない。更新前データの履歴作成と更新はトランザクションで実行する。

### 互換性と表示

保存キーstarlight-rpg-v1、形式v:2を維持する。仲間はcharacterIdを補い、エリア討伐数と解放はzoneIdsで並び替えに対応する。古いv1/v2は従来の移行処理を使用する。移行時に旧進行を勝手に消さない。

戦闘開始時に定義のスナップショットをセーブへ含め、戦闘終了後の確定保存で外す。APIの公開版は起動時に取得し、起動後やクリック待ち中に差し替えない。画面は従来の行動開始→クリック→結果→クリックの順で進める。

定義のプレビューは別キーへ保存し、通常キー・クラウド進行を更新しない。取得済みの公開定義はブラウザへキャッシュする。必要なIDが手元にない場合は進行の初期化ではなく、読み込みを停止する。

### 開発・運用

Node.js 24以上。npm ci → npm run content:sync → npm run dev。

npm testはデータ検証・既存ゲーム・実SQLiteのAPIテスト。npm run test:e2eは実ブラウザでゲームと編集/公開/クラウド復元を検証する。E2EのDBはwork/playwright.sqliteで、通常の.local/rpg.sqliteと分離。
