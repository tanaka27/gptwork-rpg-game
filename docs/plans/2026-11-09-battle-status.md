# 戦闘コマンド中の味方ステータス

- 状態：承認済み
- 設計版：v1
- 設計作成者：/root
- 要求：戦闘中央の味方からステータスを開く。主人公のコマンド中のみ開き、敵/仲間の自動行動中はクリックでメッセージを進める。

## 目的・受け入れ条件

1. 戦闘中、主人公の通常コマンド入力待ちに味方4人の顔/名前/状態欄を押すと対象の詳細がダイアログに表示される。戦闘不能者も対象。
2. HP/MP、攻撃力、守備力、賢さ、素早さ、うんのよさを既存仲間画面と共通の計算・カード表示で示す。
3. 閉じる/Escで戻り、選択した味方へフォーカス復帰。状態・ターン・道具・MPを消費しない。
4. 非戦闘/スキル一覧・詳細/道具対象選択中は詳細を開かず、回復の操作を維持。
5. メッセージ待機中は味方欄も既存の冒険画面キャプチャ処理で1クリック1件送る。自動行動中の回復対象欄はdisabledボタンから通常表示に戻し、送りを阻害しない。

## 対象範囲・実装設計

- dist/party.js：characterStatusCardを仲間詳細と共有。canInspectBattleCharacterはstate.enemy、commandResolve、!busy、skillMenuMode==='commands'を要求する。描画・クリック処理の両方で条件確認。
- 通常コマンド中だけ味方欄をbutton（aria-haspopup=dialog）にし、共通modalを開く。固有の見出しIDをaria-labelledbyから参照し、closeで属性を除去。ネイティブdialogでEscとフォーカス復帰を利用。
- 戦闘メッセージ送りのpartyStatus除外を撤去。既存のpreventDefault/stopImmediatePropagationで二重送りを防ぐ。
- busy中は回復対象ボタンを生成せず、通常の味方表示にする。pendingItem保持/次の入力時の対象選択を維持。
- bootstrap/indexのキャッシュクエリ更新。既存styleを利用し、API・計算式・セーブ形式・公開定義は変更しない。
- README/GAME_SPEC/HANDOFF/DEVELOPMENT/CHANGELOG更新。
