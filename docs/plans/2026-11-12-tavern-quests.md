# 街の酒場と依頼

- 状態：検証済み（反映待ち）
- 設計版：v2
- 要求・背景：各街の酒場で依頼を選んで受注し、条件を達成して報告すると記載報酬を一度受け取れるようにする。
- 設計作成者（子）：Codex子エージェント

## 目的・受け入れ条件

- 3つの街に「酒場」を設け、依頼一覧で条件・報酬・進捗・状態を確認できる。
- 依頼を選択して受注し、条件達成後に酒場で報告すると報酬を受け取れる。未受注・未達成・完了済みの報告と二重受取は処理側で拒否する。
- 進行は再読込後も保存され、旧 `v:2` セーブは失われず村長報酬も重複しない。

## 対象範囲

- 変更するファイル・機能：`shared/quests.js`（固定依頼・進捗・状態検証）、`shared/save.js`（セーブ検証）、`dist/index.html` / `dist/game.js` / `dist/workspace.css`（酒場UIと操作）、関連するロジック・E2Eテスト、`docs/GAME_SPEC.md`、必要な `docs/BACKEND.md`・`docs/HANDOFF.md`・`CHANGELOG.md`。
- 影響する既存仕様・関連文書：`GAME_SPEC.md` の街と依頼報酬、`BACKEND.md` の `v:2` 保存互換、`IMPLEMENTATION_WORKFLOW.md`。
- 対象外：依頼の追加・編集用Admin UI、期限、ランダム依頼、放棄、素材納品、サーバー側の新API。

## 実装設計

- 各街に共通の酒場掲示板を置き、同じ一覧から依頼を選ぶ。受注と報告はどの街の酒場でも行える。同時受注は1件までとし、報告または完了後に次を受注できる。
- 固定依頼はゲームルールとして `shared/quests.js` に置き、コンテンツJSONには加えない。条件は討伐総数だけで判定し、コンテンツ内の素材・敵・街IDは参照しない。全街に同じ掲示板を出すことで、コンテンツ管理画面や公開定義に依頼用スキーマを加えずに済む。

| 依頼 | 条件 | 報酬 |
| --- | --- | --- |
| 村長の討伐依頼（既存報酬） | 累計5体討伐 | 100 G、生命の霊薬2個 |
| 見習い討伐依頼 | 受注後に3体討伐 | 35 G |
| 熟練討伐依頼 | 受注後に8体討伐 | 90 G、生命の霊薬1個 |

- セーブへ `questState: { active: { id, acceptedAtTotal } | null, completedIds: [] }` を追加する。新規依頼は受注時の `total` との差で進捗を出し、報告時にも現在の討伐数から条件を再判定する。報酬付与時は先に完了状態を確定してから所持金・道具を加算する。
- 既存の村長報酬を最初の依頼へ統合し、条件と報酬を変えない。`claimed:true` の旧セーブは初回読込時に `completedIds` へ反映し、`claimed:false` は未完了として扱う。旧セーブの累計討伐数は最初の依頼に限り受注前分も数えるため、以前と同じ報酬を受け取れ、受領済みなら再受領できない。受領時は既存 `claimed` も `true` に保つ。
- `v:2` は維持する。依頼状態のない旧 `v:2` は既定の依頼状態を補う。`shared/save.js` は新状態がある場合に不明ID、重複完了ID、負数・未来の受注基準値、完了済み依頼の再受注、`claimed` と最初の依頼の完了状態の矛盾を拒否する。旧セーブに状態がないこと自体は許容する。
- 依頼条件は総討伐数のみなので公開済み定義・raw DB snapshot・Admin UI・`GameContent.withJobs` に変更を加えない。公開定義のclone補完や依頼参照削除安全性の追加処理も不要。セーブ検証で依頼IDを固定カタログと照合する。
- 報酬の消耗品IDは現在の公開定義から取得できる `consumables` に存在するか受注時と報告時に確認する。報酬IDがない依頼は掲示板に理由を表示して受注・報告を無効化し、操作処理でも再確認してセーブ・報酬を変更しない。この境界検査は実行時だけに行い、コンテンツ/Admin/clone方式は変更しない。
- UIのボタン無効化に加えて、受注・報告アクションが街、現在の受注、条件、完了状態を再検証する。異常な操作は報酬や依頼状態を変えない。

## 検証計画

- ロジック・セーブテスト：3依頼の受注・進捗・条件未達報告・完了報告・二重受取、旧 `claimed` の両状態、`v:2` 移行、各不正状態のvalidator拒否を確認する。
- Playwright：酒場の表示、条件・報酬・進捗、受注・報告、3街での利用、再読込後の状態、PC幅・モバイル幅、console/pageerrorを関係E2Eで確認し、変更画面のスクリーンショットを目視する。その後 `npm test`、全E2E（`workers=1`）、`npm run package:site` を実行する。
- 反映・復旧方法：親が通常のcommit/push後、既存Sitesへ反映する。復旧は直前の `main` commitへ戻して再反映する。保存キー・形式は維持し、追加状態を旧読込時に補えるため、コードを戻しても既存セーブは読み込める。
- 検証は承認済み実装後に子が一括して担当し、対象コードを変えていない通過済み確認は再実行しない。
