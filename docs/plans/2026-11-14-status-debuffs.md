# 状態異常（攻撃ダウン・守備ダウン）

- 状態：承認待ち
- 設計版：v1
- 要求・背景：強化効果（鼓舞・気合い）と同じ要領で、状態異常を敵と味方の両方に導入する。種類は攻撃ダウン・守備ダウン。付与手段は新しい特技（味方）と魔物の行動（敵）。
- 設計作成者：Claude Code

## 目的・受け入れ条件

- 味方の新しい特技で、敵1体または敵全体に攻撃ダウン・守備ダウンを付けられる。
- 一部の魔物とボスが、通常攻撃の代わりに味方へ攻撃ダウン・守備ダウンを付けることがある。
- 効果は倍率とターン数で決まり、強化効果と同じ規則で減って切れる（付与したターンは減らさず、ラウンド終了ごとに1減る。同じ種類は重ならず、再付与で残りターンを更新する）。
- 戦闘不能・撃破・勝利・逃走・全滅で解除し、次の戦闘へ持ち越さない。
- 敵の絵の上と味方の状態欄にアイコンと残りターンを出し、ステータス詳細と敵情報に倍率と残りターンを表示する。
- 戦闘中に再読み込みしても状態異常が続く。既存の `v:2` セーブ、旧公開定義、旧 `battleContent` はそのまま読める。

## 対象範囲

- 変更するファイル：`shared/rules.js`（記録・検証・正規化・実効値・ターン経過）、`shared/content.js`（効果種別・特技と魔物の行動の検証）、`shared/save.js`、`dist/party.js`（戦闘処理・表示）、`dist/game.js`（敵表示・ヘルプ）、`dist/style.css`、`dist/admin/`（効果の編集）、`content/game.json`、生成物（`npm run content:sync`）、`dist/index.html` の `?v=`

- 対象外：毒・眠りなどダメージや行動不能を伴う状態異常、状態異常を治す道具・特技（ターン経過と戦闘終了で解除。必要なら次の案件）、命中率・耐性、敵の強化効果

## 実装設計

### 効果の定義

- 効果種別に `attackDown` と `defenseDown` を追加する。形式は `{ type, multiplier, turns }`。`multiplier` は0.3以上1未満、`turns` は1〜99の整数とする（`attackBuff` の検証と対称）。
- 特技に `effect: "debuff"` を追加する。`type` は `magic` とし、会心は発生しない。`effects` は弱体効果1件だけ。`target` は省略時が敵1体、`"allEnemies"` なら敵全体。道具には弱体効果を付けられない。
- 魔物に省略可能な `actions` を追加する：`[{ id, name, rate, target: "ally" | "allAllies", effects: [弱体効果1件] }]`。`rate` は0より大きく1以下。`actions` がない魔物は今までどおり通常攻撃だけを行う。

### 戦闘処理

- 敵の番：強攻撃のターンは必ず通常攻撃（強攻撃とぼうぎょの駆け引きを残す）。それ以外は `actions` を順に `rate` で抽選し、最初に当たった行動を使う。どれも当たらなければ通常攻撃。行動は開始メッセージ「〇〇の惑わしの羽音！」→ 結果メッセージ「リナの攻撃力が下がった（3ターン）。」の2段階で、既存の行動の流れに合わせる。
- 味方の弱体特技：反映直前に対象とMPを再確認し、無効ならMPを消費せず見送る（既存の規則と同じ）。全体の場合、結果メッセージは1件で「敵N体の守備力が下がった。」とする。
- 実効値：
  - 味方の攻撃力：`floor(基本攻撃力 × 強化倍率 × 弱体倍率)`
  - 味方の守備力：`floor(守備力 × 弱体倍率)`
  - 敵の攻撃力・守備力：`floor(定義値 × 弱体倍率)`
  - これらの値を `CombatRules.physicalDamage` に渡す。計算式そのものは変えない。魔法・回復は影響を受けない。会心は守備力を無視するため、守備ダウンは関係しない。
- ターン経過は、強化効果のターン経過と同じタイミングで行う。切れたら「〇〇の攻撃力が元に戻った。」と表示する。

### 保存形式

- 新しい省略可能な項目 `state.debuffs = [{ side: "ally" | "enemy", target, type, sourceId, multiplier, remainingTurns, appliedTurn }]` を追加する。`target` は味方なら `characterId`、敵なら `state.enemies` の添字。倍率は付与時の値を記録し、戦闘中に定義が変わっても結果が変わらないようにする。
- `state.buffs` は変更しない。保存キー `starlight-rpg-v1` と形式 `v:2` も変えない。`debuffs` がない旧セーブは空配列として扱う。
- 正規化（`normalizeDebuffs`）で、戦闘外、対象が存在しない・倒れている、範囲外の値、同じ対象と種類の重複を取り除く。検証（`validateDebuffs`）は `validateBuffs` と同じ方針でエラーにする。上限は（味方の人数＋敵の数）× 2件。

### 互換性

- 旧公開定義や、ジョブを明示したDB公開版には、新しい特技も魔物の行動も自動では入らない（全体攻撃特技を追加したときと同じ方針）。ジョブ省略の旧定義・旧 `battleContent` には、`withJobs` で標準特技として補われる。
- 魔物の行動は、戦闘開始時の `state.enemies`（定義のコピー）が持つ `actions` を使う。旧セーブの敵は `actions` を持たないため、通常攻撃だけを行う。
- 管理画面：効果の選択肢に2種を追加する（初期値は倍率0.7・3ターン）。魔物の行動の編集UIは今回は作らず、JSONの検証だけを行う。この点は管理画面に表示する。

### 異常系・リスク

- 敵の添字がずれる心配：`state.enemies` は戦闘中に並べ替えないため、添字で固定できる。撃破した時点で、その敵の記録を消す。
- 難度：味方全体への弱体は、ボス戦の難度を上げる。PlaywrightとロジックでLv目安（ゴーレム Lv8前後、竜 Lv12前後）のシミュレーションを行い、数値を調整する。
- 表示の詰まり：スマホ幅で強化と弱体のアイコンが並んでも、名前やHP欄と重ならないことを確認する。
