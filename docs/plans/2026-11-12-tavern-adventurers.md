# 酒場の冒険者一覧と行動tick

- 状態：検証済み（実装承認済み）
- 設計版：v1
- 要求・背景：酒場にその街にいるNPC冒険者を一覧表示し、選択すると個別詳細を表示する。NPCは100人で、探索や移動の行動tickに応じて隣接ノードへ移動する。世界状態はセーブごとに独立する。
- 設計作成者（子）：Codex子エージェント

## 目的・受け入れ条件

- 固定ID・重複しない名前を持つ100人の名簿を用意し、各人の職業、Lv、HP、MP、攻撃、防御、賢さ、運、素早さを個別に定義する。NPC能力は旅団共通Lvに連動せず、成長・雇用・戦闘は対象外。
- 初期位置は街3か所に34・33・33人を決定的に割り当てる。酒場には現在の街ノードにいる人だけを表示し、一覧の選択で能力と現在ノードを表示し、一覧へ戻れる。
- 通常の「探索する」を開始できた回数を数え、3回ごとに1 tick進める。探索の端数はノード移動や再読込をまたいで保持する。ボス戦・道中遭遇は探索回数に加えない。
- 道中の有効な「先へ進む」操作1回ごとに1 tick進める。移動先の選択、引き返し、無効操作は加算しない。開始から到着までの操作回数は定義値に従い、進行stepごとに一度だけ加算する。道中遭遇を起こしたstepも1 tickとする。
- 各tickでNPCごとに25%で隣接ノードへ移動し、75%で現在地にとどまる。移動先は現在ノードの`links`だけから等確率で選ぶ。位置・探索端数・乱数状態を保存し、再読込・クラウド復元後も同じ状態から再開する。
- 既存 `v:2` セーブにシミュレーション状態がない場合は初期状態を補い、進行を失わない。セーブ形式と既存APIを維持し、壊れたNPC状態はNPC部分だけを安全な初期状態へ補正する。

## 対象範囲

- 変更するファイル・機能：`shared/adventurers.js`（固定名簿・初期状態・tick・状態検証/補正）、`scripts/sync-content.cjs`（新共有モジュールの同期）、`shared/save.js`（新状態の検証）、`dist/index.html` / `dist/game.js` / `dist/workspace.css`（酒場内の冒険者・依頼表示、詳細操作、行動tick）、関連するロジック・E2Eテスト、`docs/GAME_SPEC.md`、`docs/BACKEND.md`、`docs/HANDOFF.md`、`CHANGELOG.md`。
- 影響する既存仕様・関連文書：`state.node`と`nodes[].links`による地図、道中の`journey.step`、通常探索の戦闘開始、localStorageと所有者別クラウドセーブ。
- 対象外：全プレイヤー共通状態、サーバーAPI/DB変更、コンテンツ管理画面のNPC編集、NPCの戦闘・成長・雇用・依頼、地図上の人物アイコン。

## 実装設計

- 名簿は固定100件の内部ゲームデータとして `shared/adventurers.js` に置き、公開コンテンツJSONや管理UIには追加しない。安定したID、固有名、職業、Lv（1〜30）と各能力値を名簿として確定する。名簿はセーブに複製せず、セーブは `adventurerState: { tick, explorationProgress, rngState, locations }` のようにtick、探索端数、乱数状態、NPC IDごとのノードIDだけを持つ。
- 初期配置は名簿順に3街へ均等割当する。tick開始時の100人分の旧位置を基準に各人の移動を決め、一巡後に新しい位置を反映する。ノードにとどまる選択肢は常に有効とし、NPC移動は地図の隣接`links`に従う。プレイヤー用のエリア解放条件はNPC移動に適用しない。
- 乱数は初期化時に決めた固定seedの専用PRNGを使い、現在状態をセーブする。各tickで名簿順に移動判定し、移動時のみリンク候補から行先を選ぶ。`Math.random`、実時間、タブを閉じていた時間には依存させない。
- 通常探索は開始可能性を検証した後に探索端数を1加算し、3に達したら0へ戻して1tickを実行する。戦闘開始時に一度だけ処理するため、保存中の戦闘を再開しても二重加算しない。道中は`advanceTravel`でstepが実際に進んだ後に1tickを実行する。道中到着処理`finishTravel`はtickを進めず、到着step・通常step・遭遇stepを二重計上しない。
- 既存酒場内に「冒険者」「依頼」の切替表示を設け、冒険者一覧を初期選択にする。行は名前・職業・Lvを示し、クリック/タップで詳細を開く。詳細にはユーザー承認済み能力項目と現在ノード名を表示し、一覧へ戻る操作を設ける。既存の依頼受注・報告は「依頼」側に維持する。長い一覧は酒場内スクロールとし、PC/スマホで操作できるようにする。
- `v:2`を維持する。`adventurerState`がない既存保存は有効とし、読込時に決定的な初期状態を設定する。新状態が不正ならNPC状態だけ初期化し、プレイヤーの他の進行を保持する。クラウド保存は既存JSON保存経路で状態を保持する。セーブ検証はtick/探索端数/PRNG範囲、100 IDの過不足・重複、各位置ノード参照を検査する。
- NPCのノード参照も既存SaveRulesの定義参照検証へ含め、保存済みNPC位置を削除する公開定義変更は既存クラウドセーブと同様に拒否する。API・DBスキーマ・セーブキーは変更しない。
